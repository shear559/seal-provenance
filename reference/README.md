# SEAL Reference Package

The executable artifacts accompanying *A Universal Cryptographic Sealing
Primitive for Digital File Provenance in the Age of Generative AI*,
**Version 1.1 — Final Research Edition** (Appendices D–E).

Every number in Appendices D and E of the paper is regenerated by the
scripts in this directory. Run order does not matter; all are standalone.

| File | What it produces |
|---|---|
| `seal_encoding.mjs` | **The normative v1 commitment encoder** (EIP-712 domain `SEAL`/`"1"`, `Seal712` type string, `guid = keccak256(commitment ‖ signer)`). Any independent implementation must reproduce its outputs bit-for-bit. |
| `seal_demo.mjs` | Appendix D.1–D.6: public + confidential seals, tamper evidence, cross-chain replay rejection, the 100k-candidate dictionary experiment. Writes `SEAL_test_vectors.json`. |
| `vectors_v2.mjs` | Appendix D.7: the 17-vector v2 conformance suite (edge-case files, confidential openings, multi-attestation, declaredTime bounds, chunk-tree fragment proof, batch inclusion, replay matrix, real ML-DSA-65 dual-signature). Writes `SEAL_test_vectors_v2.json`. |
| `SealRegistry.sol` | The §4.15 reference registry: `submitSeal`/`submitBatch`/`commit`/`reveal`/`revoke`/`checkpoint`/`renew`/`sealFee`. No owner, no upgrade proxy, no admin functions; the fee is an immutable constructor parameter. |
| `run_evm_tests.mjs` | Compiles (solc-js 0.8.35, optimizer 200, viaIR) and runs the 15-assertion in-EVM suite (@ethereumjs/vm 10, cancun, chainId 11155111) incl. byte-for-byte client↔contract digest conformance. Writes `gas_report.json`. |
| `bench.mjs` | Appendix E.1–E.2 client-side microbenchmarks + Merkle batching table. Writes `bench_report.json`. |
| `measure_bundle.mjs` | Verification-bundle (Appendix A shape) size measurement from real vector data. |

```bash
npm install          # ethers@6, @noble/post-quantum, solc, @ethereumjs/*
node seal_demo.mjs
node vectors_v2.mjs
node run_evm_tests.mjs   # expect "== result: 15/15 =="
node bench.mjs
node measure_bundle.mjs
```

Notes:
- All keys are the well-known Hardhat/Anvil development accounts — published
  test material, never to be used in production.
- ECDSA signing is deterministic (RFC 6979); ML-DSA-65 signing uses
  `extraEntropy: false` — both required for bit-reproducible vectors.
- `commit()` gas varies by ±~12 across runs (zero-byte calldata cost of the
  random nonce); every other gas figure is deterministic.
- History note: the v1.0 edition's Appendix D digests were produced by a
  generator whose EIP-712 parameterization was never published and is not
  derivable from the paper; v1.1 replaces them with the values of this
  package, which the paper now fully specifies.
